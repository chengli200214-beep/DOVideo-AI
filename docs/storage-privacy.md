# MinIO 私有产物与已有桶策略

服务启动时会读取产物桶的访问策略。新桶及没有桶策略的已有桶可继续使用；针对指定身份的读取授权和仅包含拒绝规则的策略保持原样。服务账号需要具备该桶的 `s3:GetBucketPolicy` 权限，策略无法核对时服务会拒绝启动。

旧版本留下的匿名读取策略不会随 `minio.public-read=false` 自动消失。当前服务检测到通配主体拥有 `s3:GetObject`、`s3:GetObjectVersion` 或覆盖这些动作的授权时，会拒绝启动并指出原因。检查也覆盖可能允许匿名读取的 `NotPrincipal` / `NotAction`。当前实现保守地检查授权语句，不计算复杂条件与拒绝语句的最终组合，因此通配主体带 IP 或其他条件的读取授权仍会阻止启动；可由管理员改用明确的身份授权。应用不会自动删除或改写现有策略。

遇到“存在匿名读取策略”时，在 MinIO 控制台把该桶的匿名访问设为关闭，并保留需要的指定身份授权。也可以由管理员先核对桶用途，再使用已配置凭据的 MinIO Client alias 执行：

```shell
mc anonymous get <alias>/<bucket>
mc anonymous set none <alias>/<bucket>
```

将 `<alias>` 替换为已配置的 MinIO Client 别名，`<bucket>` 替换为本项目 `minio.bucketName` 的值；命令中的尖括号不保留。示例不包含访问密钥。

`set none` 会修改桶策略。执行前应检查并备份原策略；含多种授权的共享桶优先由管理员精确调整策略，保留其他业务所需的身份权限，或为本项目使用独立私有桶。不要假定该命令会保留任意混合策略的全部其他授权。完成后重启应用；不需要重新生成视频或删除已有产物。

视频、参考图和成片继续通过应用的所属用户校验及短时效预签名地址访问。验收使用本地 MockWebServer 模拟新桶、无策略桶、已有公开桶和策略权限不足，不修改真实 MinIO 桶。
