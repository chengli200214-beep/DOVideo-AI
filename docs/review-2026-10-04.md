# AIGC 创作平台修复与扩展（2026-10-04）

本轮基于 `18a6aff` 的代码审查，完善已能产出真实视频的创作平台。新增功能和回归使用 Mock 或本地协议替身，不发起新的 DeepSeek、SiliconFlow 或 Seedance 付费请求。既有真实联调记录仍见 [Seedance 验收](acceptance/seedance-real.json)。

## 已修复

| 原问题 | 修复后的行为 |
| --- | --- |
| 关闭的供应商任务占据每批最前面的 8 个位置，后面的可执行任务一直排不到 | 暂不可执行的任务条件更新下一次检查时间，让出队列位置；保留原状态和授权，不跨入付费提交 |
| 排队时间被计入 24 小时查询期限，旧任务刚开始就超时；人工恢复又立即超时 | 新增真实提交时间和持久化查询截止时间；人工恢复延长原远端任务的查询窗口，保持原 request ID |
| 修改一句字幕就不能再选择旧修订的视频，迫使全部镜头重新生成 | 按稳定镜头 ID、提示词、负向提示词、种子、参考图和画幅比较兼容性；字幕、标题、口播调整复用旧视频，新成片快照使用当前确认稿 |
| 切工作区、刷新或断网丢失编辑；旧响应可能写入新账号工作区 | 草稿按账号与项目保存在本机，有版本冲突提示、明确应用／丢弃和 JSON 导出；请求校验会话和组件生命周期 |
| 查询短暂失败后页面停止更新 | GET 查询最多 5 次退避重试，联网后重新查询；POST 提交保持原有显式意图及幂等机制，不因断网自动重发 |
| MySQL 用户名不区分大小写、Redis 失败计数区分大小写，可通过改变字母大小写绕过限制 | 登录失败键统一小写；Lua 原子增加计数并设置或修复过期时间；成功登录清理同一键 |
| 老桶已存在匿名读取策略，忽略 `public-read` 开关无法消除该策略 | 启动时读取桶策略，发现匿名读取授权或无法核对策略则拒绝启动，提供管理员处理方法，不擅自改写已有桶策略 |

兼容性判断不使用期望时长、标题等未提交给视频供应商的字段；这些文本不应导致额外的视频模型调用。提示词等生成输入改变后，旧版本仍可查阅，但不能用来满足新确认稿的镜头选择。历史活跃或结果未知任务继续阻止同镜头的新提交。

## 新增功能

- 项目库：关键词搜索、游标分页、归档、恢复；已归档项目保留全部分镜、产物、额度和历史，只读查看与下载仍可用。活动任务或未知提交阻止归档，服务端也检查写操作。
- 参考素材库：查看、私有预览、再次选用已上传图片；仅允许删除未引用的参考图。历史项目、分镜和任务引用受保护，旧 JSON 数据也保守检查。
- 对象清理队列：删除操作与数据库队列同事务提交，存储故障有限重试、失败后可手动恢复；UUID 租约防止旧工作者覆盖新状态，独立对象名防止旧清理误删同内容的新上传。
- CI：保留原单元测试与扩展测试，增加独立 AIGC 应用打包、静态资源检查及隔离 MySQL／Redis／MinIO／FFmpeg 综合验收。Linux 和 Windows 验收入口都清除真实模型密钥并关闭调用开关。

使用方法及 API 见 [项目库与素材库](project-library.md)，桶策略升级见 [存储隐私说明](storage-privacy.md)。素材删除不会回收任何历史生成视频，也不是全桶孤儿对象扫描。

## 数据升级

- V10 增加 `generation_tasks.submitted_at`、`poll_deadline_at`。能够从旧提交事件恢复的时间会回填；已活跃但没有截止时间的任务首次领取时获得一个持久化查询窗口，此后重启不会持续延长。
- V11 增加项目归档字段、项目库索引、素材引用表和对象清理队列。新引用和删除锁定同一素材行，并以外键保护并发；删除先提交时，新引用失败并回滚。
- 升级实例应统一使用新代码及新迁移，不能让旧写入程序继续绕过素材引用登记。历史 JSON 引用保护用于升级前已经存在的记录。

后端完整回归通过 **145 项**，失败、错误和跳过为 0。覆盖队列阻塞、旧任务期限迁移、人工查询恢复、跨修订复用、归档写保护、超过 50 项的分页、字面通配符、账号隔离、素材引用与删除并发、清理重试和失效租约，以及登录限制和桶策略检查。

前端完整回归通过 **77 项**，生产构建通过。补充覆盖归档响应期间的草稿保护、失效会话释放操作状态，以及当前账号全部本机草稿的参考图删除保护。

真实 MySQL／Redis／MinIO／FFmpeg 综合测试 **1 项、21 个检查通过**。新增检查验证实际 SQL 分页与特殊字符搜索、项目归档和恢复、MinIO 对象清理及引用拒删、Redis Lua 大小写统一限流和过期解除。首轮发现模拟任务与后台调度器的领取竞争，已将测试的创建和领取放入同一事务，重新执行综合测试通过；生产领取条件未放宽。临时测试容器已清理，日常项目数据保留。脱敏记录见 [本轮验收 JSON](acceptance/review-2026-10-04.json)。

独立应用完成打包并检查入口和内置前端，在本机实际启动；现有数据库备份后由 V9 成功升级至 V11。浏览器验证工作台可访问，旧登录会话过期后返回登录入口。运行模式为 Mock，付费及历史供应商查询开关关闭，本轮新增付费调用为 0。GitHub Actions 的远端结果以对应提交的运行记录为准，本轮本地验证不代表远端 CI 已运行。

运行验收中另处理了 Docker Desktop 残留 socket 导致的启动失败：隔离临时通信目录后引擎恢复，原有项目容器及数据保留。复发时的限定恢复步骤见 [Docker 恢复说明](docker-recovery.md)。

后续重启实测发现，本机正常退出 Desktop 后直接重启仍可复现同样错误。已将限定恢复接入项目入口：停止状态先备份两处通信目录再启动，健康状态直接复用；固定本机引擎，恢复依赖后复核应用进程、端口和 MinIO 就绪，已有持久卷缺少凭据时拒绝生成替代密码。新增 26 项 Windows 启动测试在 PowerShell 7 和 5.1 均通过；真实恢复耗时 15.7 秒，重复启动不替换进程，数据库前后快照一致。详见 [启动恢复验收](acceptance/docker-startup-recovery.json)。

本轮保留用户已确认移出范围的三项：实际账单核对、正式人工评分、历史 SiliconFlow 未知提交核实。没有把本地测试解释为生产规模或模型效果提升的证据。
