# 2026-10-05 复审修复

本轮修复六类可复现问题，不提交真实模型请求。

| 问题 | 修复后的行为 |
| --- | --- |
| 扩展把下载任务 UUID 当作媒体 ID | 提交链接后轮询下载任务，完成后使用 `media.id` 分析；失败、取消和登录过期停止后续请求 |
| 分镜模型返回撤销期间的人工确认 | 项目行锁内检查活动规划任务，禁止期间确认或提交新镜头；已有未完成或未知镜头也阻止新规划；返回时再次检查确认快照，旧实例的并发确认保留为冲突结果 |
| Redis 回执丢失导致重复入库或假失败 | 媒体唯一 `ingest_key` 与媒体行同时提交；分片重试查询数据库；链接任务存入 MySQL，可用已提交媒体修复丢失的完成状态 |
| 跨标签账号变更后页面身份与 token 不一致 | 同步 storage 事件；事件尚未到达时，请求和会话守卫拒绝旧页面操作并同步账号；旧操作响应失效，草稿仍按当前账号隔离 |
| 漏填产物域名仍提交收费视频 | Seedance 能力、提交及恢复入口检查非空的精确域名列表；启动脚本拒绝空列表、通配符、地址及路径 |
| 参考图已写对象但元数据失败后变成孤儿 | 写对象前独立提交清理意图；上传与清理共用数据库行锁；失败或崩溃后恢复清理，删除前核对已提交的素材元数据 |

## 升级

正常启动由 Flyway 自动应用 `V12__durable_media_ingest.sql` 和 `V13__planning_confirmation_snapshot.sql`。新增字段允许旧媒体和旧规划任务保留原数据，无需清空数据库、Redis 或 MinIO。

旧 Redis 链接任务仍可在原 TTL 内查询；新链接任务以数据库为真源，查询窗口仍为 24 小时。尚未完成的下载不会在重启后自动重发，超过既有排队或运行期限后显示中断；如果媒体已提交，状态查询会找回完成关联。分片上传仍需 Redis 保存未完成分片和协调合并锁。

没有确认快照的旧规划任务遇到已确认项目时，将结果保留为 `CONFLICT`，不撤销确认，不自动重发模型调用。
