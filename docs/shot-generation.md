# 镜头生成与局部重生成：第三阶段

已接通「确认分镜 → 镜头任务 → 查询状态 → 私有产物归档 → 局部重生成」。沿用现有 GenerationService、任务状态机、worker 和 MinIO，不另建模型提交器。默认 Mock、付费关闭；Mock 视频为固定测试样例，不用于评价模型效果。

## 页面操作

打开 `/?storyboard`，登录、创建或选择项目，保存并确认分镜。在下方「镜头生成」区域配置最多生成版本数和预留预算上限，再生成尚未提交的镜头。Mock 预算为 0，但仍限制版本数；建议演示额度 12，包含首次生成和后续重生成。

页面展示每个镜头的生成版本、绑定的分镜版本、模型、任务状态、预留金额和费用状态。任务处理中每 5 秒查询一次；刷新失败停止轮询并提示手动刷新，提交结果未知也停止轮询。完成后可按需读取已归档视频。切换项目、账号或退出页面会停止旧轮询并忽略迟到的响应。

「仅重生成此镜头」只创建目标镜头的新版本，不重跑其他镜头。最新生成仍在处理或提交结果未知时不可重生成。修改提示词或参考图片需在分镜中编辑、保存并重新确认，生成时绑定新的不可变分镜版本；版本编号在每个分镜版本与镜头内递增。

分镜确认本身不会提交生成任务。保存或切换项目不会自动提交任务。当前已接入镜头选择、独立 FFmpeg 成片及人工评测，参见 [完整平台说明](creator-platform.md)。

## 接口

所有接口沿用 `/generation/**` 登录拦截与项目所有权校验，跨用户读取返回 404。

| 方法 | 路径（前缀 `/generation/projects/{id}`） | 作用 |
| --- | --- | --- |
| POST | `/budget` | 配置 `{maxVersions,costLimit}`；已有生成版本后仅允许重复同一配置 |
| GET | `/generation-quote?revision=1` | 当前确认稿的模式、模型、画幅对应尺寸、可用性、单任务预留金额和项目额度；无模型调用 |
| POST | `/generations` | `Idempotency-Key` + `{revision,mode,shotIds}`；首次 201，重复 200 |
| GET | `/generations` | 历史版本、任务及预算台账，含旧分镜版本；无自动提交 |

`mode=INITIAL` 可选择 1–8 个尚未生成的镜头；`mode=REGENERATE` 每次只接受一个已生成镜头。相同 key 的排序归一化请求重放同一批次，即使后来分镜已编辑；相同 key 不同请求返回 409。主动重生成另一次需新 key。网页提交响应丢失后可重试上次提交；sessionStorage 只保存账号与项目范围内的请求摘要及 key。

技术恢复使用原接口：`POST /generation/tasks/{taskId}/retry` 仅恢复已有 requestId 的查询或归档；未知提交通过 `/reconcile` 补录 `{requestId}`。两者保留原生成版本，不增加项目预算或重新提交模型。未经核对 requestId 不允许盲目重生成未知任务。

## 持久化与并发

V7 新增项目额度、提交批次和镜头生成版本三张表。生成版本通过 FK 关联不可变分镜修订、批次和唯一模型任务，保存镜头字段快照、预留金额以及付费授权快照。模型输入从保存稿构建：有私有参考素材 ID 使用图生视频，否则文生视频；按画幅选择已配置支持尺寸。期望时长、字幕、口播保留在镜头快照，不传给当前视频模型。

提交事务首先锁定所属项目行，检查当前稿已确认以及镜头状态，再预留整个批次额度，创建任务及版本记录。分镜编辑、确认同样更新项目行，因而与提交串行。任一镜头参数、能力或 SQL 写入失败会回滚整个批次，包括任务事件与额度；事务不执行模型请求、图片读取或对象上传。提交成功后原 worker 自动执行，应用重启按持久化任务状态恢复。

## 预算语义

- `usedVersions` 包含所有已创建的首次和重生成版本，失败也占用额度；最大 1000。项目额度不能替代全局付费授权。
- `reservedCost` 累加配置的单任务预留金额，Mock 为 0。该金额是门禁估算，不是供应商报价或账单；没有退款核对，所以失败、未知与完成任务都不自动释放预留。首次生成后额度固定。
- 付费镜头保存当时授权 ID、政策摘要及预留金额；worker 提交前重新校验，全局授权变化时在模型调用前阻止提交。全局模型名单、总任务数及预算门禁仍生效。
- Mock `actualCost=0`、`costStatus=FREE_MOCK`。尚未通过模型提交边界的付费任务标记 `NOT_SUBMITTED`，已持久化全局调用预留的任务标记 `UNKNOWN`。没有供应商账单时实际费用保持 null；提交前失败才记已知实际费用 0。
- `knownActualCost` 仅汇总已知费用，不能作为全部支出；`unknownCostTasks` 统计已经跨过调用边界且账单未知的付费任务。队列中的未提交任务也不被假定为已结算。

## 验证

本阶段验收通过：72 项后端测试、41 项前端测试和 Vue 构建；1 项真实 MySQL / Redis / MinIO 综合验收覆盖 V7 迁移、四个并发请求只建一个三镜头批次、队列重启后归档、仅单镜头重生成、额度拒绝及二次重启持久化。失败、错误及跳过均为 0，付费调用为 0。后端测试覆盖部分写入失败的事务回滚、一个剩余额度的并发竞争、过期确认稿、输入权限、未知提交、原任务技术恢复及纯数据库授权／预算检查。付费测试使用替身 provider 并断言提交从未被调用。

记录保存为 [第三阶段验收](acceptance/milestone-three.json)。登录后的浏览器完整操作尚未验收，由后端真实 HTTP 与 Vue 状态逻辑测试覆盖；原分析服务、真实模型效果、账单结算未验收。
